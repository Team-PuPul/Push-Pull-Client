# GitHub Issue Creator
 
현재 Git 저장소에 GitHub 이슈를 생성하는 스킬.  
**게임 개발(Unity)** 환경을 기준으로 동작한다.
 
---
 
## 언어 규칙 (필수)
 
- **이슈 제목**: `[태그] 한글 설명` 형식
- **이슈 본문**: 반드시 한글로 작성
- 제목 예시: `[Bug] 카드 뒤집기 시 충돌 발생`, `[Feature] 인벤토리 정렬 기능 추가`
---
 
## 전제 조건
 
- `gh` CLI 설치 및 인증 완료 (`gh auth status`)
- Git 저장소 초기화 완료 (원격 GitHub 저장소 연결)
---
 
## 워크플로우
 
### 1단계: 저장소 확인
 
```bash
# 현재 레포 확인
gh repo view --json nameWithOwner -q .nameWithOwner
 
# 현재 사용자 확인 (담당자 기본값용)
gh api user -q .login
```
 
### 2단계: 이슈 정보 수집
 
사용자의 요청에서 다음 정보를 추출한다. 불분명한 항목만 질문한다.
 
| 항목 | 기본값 | 설명 |
|------|--------|------|
| **제목** | (필수) | `[태그] 한글 설명` 형식 |
| **본문** | (선택) | 아래 템플릿 참고 |
| **라벨** | 내용 기반 자동 결정 | 아래 라벨 규칙 참고 |
| **담당자** | 현재 로그인 사용자 | 명시하지 않으면 자신으로 설정 |
| **마일스톤** | 내용/현황 기반 자동 결정 | 5.5단계 참고 |
| **프로젝트** | 내용/현황 기반 자동 결정 | 5.5단계 참고 |
 
### 3단계: 이슈 제목 생성
 
**제목 형식:** `[태그] 한글 설명`
 
| 태그 | 사용 상황 |
|------|-----------|
| `Bug` | 버그, 오류, 충돌, 예외 |
| `Feature` | 새 기능, 시스템 추가 |
| `Improve` | 기존 기능 개선, 최적화 |
| `Design` | UI/UX, 아트, 레이아웃 |
| `Docs` | 문서, 주석, README |
| `Refactor` | 코드 정리, 구조 개편 |
| `Test` | 테스트 코드, QA |
| `Chore` | 빌드, 설정, 의존성 |
 
### 4단계: 본문 작성
 
사용자가 본문을 제공하지 않으면 아래 템플릿을 기반으로 자동 작성한다.
 
**Bug 이슈 템플릿:**
```markdown
## 버그 설명
<!-- 어떤 버그인지 간결하게 설명 -->
 
## 재현 방법
1. 
2. 
3. 
 
## 예상 동작
<!-- 정상적으로 어떻게 동작해야 하는지 -->
 
## 실제 동작
<!-- 실제로 어떻게 동작하는지 -->
 
## 환경
- Unity 버전: 
- 플랫폼: (PC / Mobile / Editor)
 
## 참고 사항
<!-- 스크린샷, 로그, 추가 정보 -->
```
 
**Feature / Improve 이슈 템플릿:**
```markdown
## 개요
<!-- 무엇을 추가/개선하려는지 설명 -->
 
## 목적 및 배경
<!-- 왜 이 기능이 필요한지 -->
 
## 구현 내용
- [ ] 
- [ ] 
- [ ] 
 
## 참고 사항
<!-- 관련 문서, 레퍼런스, 디자인 시안 등 -->
```
 
**기타 이슈 템플릿 (Design / Refactor / Docs / Chore / Test):**
```markdown
## 개요
<!-- 작업 내용 설명 -->
 
## 작업 항목
- [ ] 
- [ ] 
 
## 참고 사항
<!-- 추가 정보 -->
```
 
### 5단계: 라벨 결정
 
요청 내용을 분석해 자동으로 라벨을 결정한다.
 
**기본 라벨:**
 
| 조건 | 라벨 |
|------|------|
| 버그, 오류, 크래시 | `bug` |
| 새 기능, 시스템 추가 | `feature` |
| 개선, 최적화 | `enhancement` |
| UI/UX, 아트 | `design` |
| 문서, 주석 | `documentation` |
| 코드 정리, 리팩토링 | `refactor` |
| 빌드, 설정 | `chore` |
| 테스트 | `test` |
 
**Unity/게임 특화 라벨:**
 
| 조건 | 라벨 |
|------|------|
| 씬(Scene) 관련 | `scene` |
| 셰이더, 렌더링 | `graphics` |
| 애니메이션 | `animation` |
| 사운드, 오디오 | `audio` |
| UI, HUD, 인벤토리 | `ui` |
| 카드, 덱, 패 관련 | `card` |
| 전투, 스킬, 데미지 | `gameplay` |
| 성능, 프로파일링 | `performance` |
| 네트워크, 멀티플레이 | `network` |
 
> 라벨은 여러 개 적용 가능. GitHub에 없는 라벨은 자동 생성하거나 사용자에게 안내.

### 5.5단계: 마일스톤 / 프로젝트 자동 결정

사용자가 명시하지 않아도, **현재 저장소/조직에 생성된 마일스톤과 프로젝트를 조회해 가장 적합한 항목을 자동으로 할당**한다.

#### (1) 마일스톤 조회 및 결정

먼저 열려 있는(open) 마일스톤 목록을 조회한다.

```bash
gh api repos/{owner}/{repo}/milestones --jq '.[] | select(.state=="open") | {number, title, due_on}'
```

결정 규칙:

| 상황 | 동작 |
|------|------|
| 열린 마일스톤이 **0개** | 마일스톤 미할당 (생략) |
| 열린 마일스톤이 **1개** | 해당 마일스톤을 자동 할당 |
| 열린 마일스톤이 **여러 개** | 제목/설명과 이슈 내용을 매칭(키워드, 스프린트/버전, 마감일 임박순)하여 가장 적합한 1개를 선택. 명확히 판단되지 않으면 사용자에게 후보를 제시하고 질문 |

> 할당 시에는 `--milestone "<제목>"` 형식으로 **제목 문자열**을 그대로 사용한다.

#### (2) 프로젝트 조회 및 결정

GitHub Projects v2를 조회한다. **프로젝트 조회/할당에는 `project` 스코프가 필요**하므로 먼저 스코프를 확인한다.

```bash
# 현재 토큰 스코프 확인
gh auth status 2>&1 | grep -i "scopes"
```

- `project`(또는 `read:project`) 스코프가 **없으면** 사용자에게 다음을 안내하고, 프로젝트 할당은 건너뛴 채 진행한다(마일스톤·이슈 생성은 정상 수행):
  ```
  ⚠️ 프로젝트 자동 할당에는 'project' 스코프가 필요합니다.
  아래 명령으로 권한을 추가한 뒤 다시 시도하면 프로젝트도 자동 할당됩니다:
    gh auth refresh -s project
  ```
- 스코프가 **있으면** 조직 소유 프로젝트 목록을 조회한다(소유자는 1단계의 `owner.login` 사용):

```bash
gh project list --owner <owner> --format json --jq '.projects[] | {number, title, closed}'
```

결정 규칙:

| 상황 | 동작 |
|------|------|
| 열린 프로젝트가 **0개** | 프로젝트 미할당 (생략) |
| 열린 프로젝트가 **1개** | 해당 프로젝트를 자동 할당 |
| 열린 프로젝트가 **여러 개** | 제목과 이슈 내용/라벨을 매칭하여 가장 적합한 1개를 선택. 명확히 판단되지 않으면 사용자에게 후보를 제시하고 질문 |

> 할당 시에는 `--project "<프로젝트 제목>"` 형식으로 **제목 문자열**을 사용한다.

### 6단계: 생성 전 확인
 
사용자에게 다음을 보여주고 확인받는다:
 
```
📋 이슈 생성 예정
 
제목: [Bug] 카드 뒤집기 시 NullReferenceException 발생
라벨: bug, card
담당자: @username
마일스톤: Push&Pull milestone (자동 선택)
프로젝트: Push&Pull (자동 선택)   ← project 스코프 없으면 "미할당 (권한 필요)"로 표시
 
본문:
---
(본문 미리보기)
---
 
생성할까요? (y/n)
```
 
> **반드시 사용자 확인 후 이슈를 생성한다.**
 
### 7단계: 이슈 생성
 
```bash
gh issue create \
  --title "<이슈 제목>" \
  --body "<이슈 본문>" \
  --label "<label1>" \
  --label "<label2>" \
  --assignee "<username>" \
  --milestone "<마일스톤 제목>" \
  --project "<프로젝트 제목>"
```

> `--milestone` / `--project`는 **5.5단계에서 결정된 항목이 있을 때만** 붙인다.
> 마일스톤·프로젝트가 미할당(또는 `project` 스코프 없음)이면 해당 플래그를 생략한다.
> `--project` 플래그는 `project` 스코프가 있어야 동작하며, 없으면 `gh auth refresh -s project` 안내 후 생략한다.
 
**라벨이 없을 때 자동 생성:**
```bash
gh label create "<label-name>" --color "#0075ca" --description "<설명>"
```
 
### 8단계: 결과 보고
 
이슈 생성 후 다음을 사용자에게 알려준다:
- 이슈 번호 및 URL
- 적용된 라벨 목록
- 담당자
- 할당된 마일스톤 / 프로젝트 (미할당 시 사유 — 예: 항목 없음, `project` 스코프 없음)
---
 
## 에러 처리
 
| 상황 | 대응 |
|------|------|
| `gh` 인증 안 됨 | `gh auth login` 실행 안내 |
| Git 저장소 아님 | 저장소 확인 요청 |
| 원격 저장소 없음 | GitHub 원격 연결 안내 |
| 라벨 없음 | 자동 생성 또는 사용자 선택 |
| 권한 부족 | 저장소 권한 확인 안내 |
| 마일스톤/프로젝트 없음 | 미할당으로 진행 (생략) |
| `project` 스코프 없음 | `gh auth refresh -s project` 안내 후 프로젝트만 생략, 나머지는 정상 생성 |
| 마일스톤/프로젝트 다수 | 후보 제시 후 사용자에게 선택 요청 |
